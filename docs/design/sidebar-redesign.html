现在导航选中和会话选中都是 primary.opacity(0.09)。同一种灰意味着同一种「当前」，扫视时两层会糊在一起。方案给两层两种语法：导航是页面级——accentSoft 10% 底 + 强调色图标；会话是条目级——中性 6.5% 底 + 左侧 2.5×14pt 强调竖条。

03

边界与状态

深色、最小宽度，以及几个不能省的细节
AFTER · DARK夜间 · 实际尺寸

深色不是反色，是同一套 token 换值

表面
面板底仍交给原生 List(.sidebar) 材质；设计稿的 #0E1220 只是近似，不在 SwiftUI 里写死背景。
选中
导航 accentSoft 18%；会话 9.5% 白 + 2.5pt 竖条，竖条换成 #818CF8。
状态
只有 5pt 圆点用 #34D399；引擎名回到 text3，不跟着染绿。
发丝线
1px 白 9%；分组靠标题而不是线，减少亮线在暗底上的噪点。

留白不补卡片。列表少于 10 条时下方留空，是窗口高度决定的；塞一张提示卡只会把低频内容变成常驻噪音。

宽度与状态

226pt 是当前默认值；最小 200、最大 280 都要成立。

200pt标题仍留 7 个汉字 + 时间；引擎名截到「Spl…」时只留状态点，不硬挤。
280pt时间与读数留白变大，行高不变；不把双行摘要塞进来，列表密度优先。
悬停时间淡出、「…」淡入，宽 32pt 的槽不变，行不跳。
生成中时间位换成 6pt 呼吸点，不用 spinner、不挤标题；减少动效时改为静态点。
搜索无结果「没有匹配的对话」+「清除搜索」，不显示首次使用的空态引导。
键盘导航仍走 ⌘1–⌘6、⌘,；新对话 ⌘N、搜索 ⌘F 不变，搜索展开后 Esc 只收搜索。

不做的事

这些看起来能省空间，实际会多一次点击或永久占位。

  • 不把设置并进导航列。系统级页面，底栏常驻比多一行同权链接更稳。
  • 不做可折叠分组。20 条以内，折叠省下的高度小于多出来的一次点击。
  • 不设常驻搜索框。搜索是低频动作，图标 + ⌘F 足够；常驻会永久吃掉 30pt 会话高度。
  • 不加未读红点。会话没有「未读」语义，只有「正在生成」；红点会让每条历史都像待办。
  • 不在侧栏放模型 / 引擎大卡。那是概览页的职责，侧栏只留一行读数。

实施顺序

结构一次做完，信息密度紧跟，最后才是状态。

P0 · 结构双层选中、分组标题。两件事一起改，侧栏的骨架就立住了。
P1 · 信息相对时间与悬停让位、行尾导轨。行高不变，只是把已有的数据放回行里。
P2 · 状态原地搜索、空态引导。可与搜索快捷键一起回归。
