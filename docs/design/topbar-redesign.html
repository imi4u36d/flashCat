七个页面共用一条 52pt 原生 toolbar。现在页名悬在详情栏正中、外面还包着一圈系统玻璃； 页面动作和全局状态三种形态平铺；底缘没有收口。方案 A 把页名放回内容左缘，把引擎 / 下载 / 通知 收进一枚仪表胶囊；方案 B 保留原生居中，只做降噪。两版都不增加顶部高度。

  1. 01

    页名悬在详情栏正中

    20pt / 700，离内容左缘 567pt。视线从页名跳到下面的卡片要横跨半个详情栏，页名更像标题栏里的浮标，而不是这一页的开头。

  2. 02

    页名外面还有一圈系统玻璃

    macOS 26 给 .principal 槽自动加了一层玻璃胶囊。页名越大，这圈底越像一枚独立控件；它和右侧的动作胶囊同高、同圆角，互相抢注意力。

  3. 03

    胶囊套胶囊

    引擎 / 日志 / 设置把统计、LIVE、版本号塞进页名胶囊，里面再套一层 24pt 的 dsGlassPill；两层圆角只差 2–4pt，看起来像没对齐。右边是引擎页的实拍：

  4. 04

    右侧三种形态混排

    描边胶囊（切换模型）、浅色实心动作（启动引擎）、裸文字状态（已停止）并排，中间只靠一根 16pt 竖线分组；页面动作和全局状态读起来像三个不相干的控件。

  5. 05

    底缘没有收口

    除对话页外，工具栏和内容之间没有分隔线；白色标题栏直接压在白底内容上，顶部像「没画完」。对话页自带的发丝线又只有这一页有，七页不一致。

真正的问题不是某一个控件丑。 这一行同时承担页名、页面动作、全局状态三件事，却没有分组语法： 页名没有贴住内容，动作没有主次，状态没有容器，底缘没有结束线。所以先重写这一行的结构，而不是单独去调某颗按钮。
01

改版方案：先分组，再谈样式

总高 52pt · 不新增第二行

新结构把这一行拆成三块：页名区（页名 + 一行页面读数，贴住内容左缘）、 页面动作区（最多一颗浅色主操作 + 图标动作）、全局仪表胶囊（引擎 / 下载 / 通知，固定在内容右缘）。 页名区回答「这是哪一页」，动作区回答「这一页能做什么」，胶囊回答「机器现在怎么样」——三件事各有容器，不再平铺。 不新增第二行：退回两行页头会多占 44pt，不在这次的候选里。

03

怎么落：不新增一行，也不重写弹层

只动外壳 · 数据全部复用

结构改动

  • 01
    页名放进 .navigation 槽，加 .sharedBackgroundVisibility(.hidden)。窗口标题已是 titleVisibility = .hidden，不会多出一行；页名会落在详情栏左缘，不再居中。
  • 02
    B 是同一套的兜底。保留 .principal，同样隐藏系统玻璃，页名降到 13pt；其余完全一致。
  • 03
    仪表胶囊只换外壳。现有的引擎 / 下载 / 通知三个 popover 原样保留，外面包一枚 28pt 胶囊和三段分隔线。
  • 04
    底缘线画一次。在 ConsoleShell 的 detail 顶部加 1px 线，删掉对话页自带的那条，七页统一。
  • 05
    principal 锚点。macOS 26 在没有 principal 槽时会把 trailing 动作紧贴在页名后面；放一枚 1pt 透明锚点（DSToolbarAnchor）占住槽位，动作才会贴住右缘。

读数来源（全部是现有值）

  • 01
    模型库：当前引擎的已安装 + 推荐总数 + 引擎名（与页内「推荐 7」一致；侧栏角标仍是全局计数）。
  • 02
    引擎：已安装数 / 目录总数、运行中计数；来自现有 installedCount / runningCount。
  • 03
    日志：来源标题 + LIVE / PAUSED；来自现有筛选状态。
  • 04
    设置：appVersion + chipName；现在是同一段字符串，只是从胶囊里搬出来。
  • 05
    画廊：图片 / 视频计数；概览与对话不加强行读数，保持页名 / 会话名。
